運作腳本三：諮詢 AI 物理治療師（Physio Agent）— 展示影片旁白稿

以下範例以下拉選單預設的「頭部前傾（烏龜頸）」情境撰寫，跟運作腳本一使用同一個
demo 帳號、同一個坐姿問題，前後呼應成同一個故事。若現場改選其他坐姿或改打其他症狀，
把文中對應內容換掉即可，其餘句子不變。

────────────────────────────────────────
【開場】
────────────────────────────────────────
這是智慧辦公椅專題運作腳本三的展示：諮詢 AI 物理治療師。
上一個腳本展示了系統怎麼偵測坐姿、觸發馬達提醒，這次要展示的是使用者主動
向 AI 諮詢的完整流程——重點是呈現 LLM 決策核心、MCP 工具呼叫、以及完整的
ReAct 迴圈，不是把問題丟給黑盒子、只看最後跑出一段文字而已。

────────────────────────────────────────
【Step 0：登入】
────────────────────────────────────────
一樣先登入測試帳號，取得存取權杖 Token。這個帳號已經預先設定好身高體重，
也有近 7 天的坐姿紀錄，等一下 Agent 才有真實資料可以分析。

（點擊登入後）
登入成功，帳號已取得授權，接下來所有操作都以這個帳號進行。

────────────────────────────────────────
【B.1：AI 建議 — 依當下偵測到的坐姿】
────────────────────────────────────────
這是 App 裡「取得 AI 建議」按鈕對應的情境：使用者當下被偵測到頭部前傾，
按下按鈕向 AI 諮詢。

（點擊「取得 AI 建議」後）
Agent 開始執行 ReAct 迴圈，畫面上會依序顯示每一步實際呼叫的 MCP 工具。

第一步，Agent 呼叫 get_posture_history，查詢這個使用者的身高體重 BMI、
最近幾筆坐姿紀錄，以及近 7 天的壞坐姿統計，用來判斷問題的嚴重程度跟頻率。

第二步，Agent 呼叫 search_knowledge_base，針對頭部前傾這個問題查詢醫學
文獻知識庫，確保等一下給的建議都有實證依據，不是憑空生成。

第三步，Agent 根據前面兩步查到的資訊，產生個人化的建議回覆，包含問題分析、
立即可以做的改善動作、長期預防方式，最後附上引用的文獻來源。

（結果顯示後）
可以看到，Agent 不只是回一段建議文字，畫面上完整呈現了它做了哪些決策、
呼叫了哪些工具、每個工具實際查到什麼資料——這就是 ReAct 迴圈跟傳統
function calling 最大的不同。

────────────────────────────────────────
【B.2：AI 建議 — 純症狀，不綁定特定坐姿（新功能）】
────────────────────────────────────────
這是這次新增的功能：使用者不一定要等椅子偵測到某個特定坐姿，
也可以直接描述自己的症狀發問，例如「我最近打字的時候肩膀跟脖子很痠痛」。

（點擊「純症狀詢問」後）
一樣是完整的 ReAct 迴圈，差別是這次 Agent 不會被框在某個特定坐姿類別裡，
而是純粹針對描述的症狀去查知識庫、給建議，一樣附上文獻引用。

────────────────────────────────────────
【C：每週坐姿報告（系統排程自動產生）】
────────────────────────────────────────
除了使用者主動詢問，系統也會每週自動幫使用者做一次坐姿回顧。這個功能是
後端排程，在 Linux 主機上用 cron 設定，每週固定時間自動執行，不需要
使用者做任何操作，也不是靠這個網頁的按鈕現場觸發。

排程執行的時候，會統計這個使用者近 7 天各種壞坐姿出現的頻率，一樣交給
同一套 Physio Agent 邏輯做完整的 ReAct 分析，結果直接寫成通知，
使用者打開 App 通知頁就會看到。

（點擊「查詢我的週報通知」後）
這是排程已經幫這個使用者產生好的週報內容——可以看到它自動抓出近 7 天
最常出現的問題坐姿、算出出現的頻率百分比，並且結合這個使用者的身高體重，
給出這一週的具體改善建議，跟剛才主動詢問用的是同一套 Agent，
只是這次是系統主動、定期產生，不用使用者開口問。

────────────────────────────────────────
【結尾】
────────────────────────────────────────
以上就是運作腳本三：諮詢 AI 物理治療師的完整展示，涵蓋使用者主動依坐姿
發問、主動描述症狀發問，以及系統排程自動產生週報這三種情境，
背後都是同一套 LLM 決策核心加上 MCP 工具呼叫的 ReAct 迴圈在運作。

────────────────────────────────────────
【備用句：如果選的是其他坐姿】
────────────────────────────────────────
標準坐姿：這次選的是標準坐姿，Agent 一樣會查詢背景資料跟知識庫，
確認目前坐姿良好、給予維持建議。
身體左傾：Agent 會針對左傾提出對應的核心穩定與骨盆校正建議。
身體右傾：Agent 會針對右傾提出對應的核心穩定與骨盆校正建議。
過度後仰：Agent 會針對過度後仰提出腰椎支撐與骨盆傾斜的改善建議。
久坐未動：Agent 會針對久坐提出起身活動與伸展的提醒建議。
