B.1

AI 建議 — 依當下偵測到的坐姿

呼叫 POST /api/agent，帶入偵測到的坐姿（對應 App 裡「取得 AI 建議」按鈕的預設模式）。 Agent 會依序：Step 1 查詢個人化背景（身高體重 BMI、近 7 天壞坐姿統計）→ Step 2 查知識庫 → Step 3 產生建議， 每一步都會呼叫真正的 MCP 工具，不是把整段文字直接丟給 LLM 生成。

B.2

AI 建議 — 純症狀，不綁定特定坐姿（新功能）

同樣呼叫 POST /api/agent，但這次完全不帶 posture 欄位，只送 user_message。 後端 Schema 原本規定 posture 必填，現在改成 posture、user_message 至少擇一——讓使用者不用等椅子偵測到特定坐姿， 也能直接描述症狀發問。

C

每週坐姿報告（系統排程自動產生）

這個功能是後端排程（Linux 主機用 cron，一過週日 00:00 自動執行 python manage.py weekly_advice）， 不是網頁按鈕現場觸發——排程會彙整每位使用者近 7 天壞坐姿統計，一樣交給 Physio Agent 做完整 ReAct 分析， 結果直接寫進通知，不需要使用者主動詢問。下面的按鈕只是查詢 GET /api/notification/history， 顯示資料庫裡「已經產生好」的週報通知（demo 前已先手動跑過一次 weekly_advice 產生範例資料）。
